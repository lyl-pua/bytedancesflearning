# DeerFlow 2.0 在 Windows 上跑起来（初学者版运行手册）

> 这份文档只解决一件事：**从零把 DeerFlow 在本机跑起来，并且真的能用**。
> 里面的命令都是在本机（Windows + PowerShell、没有 make / 没有 nginx / 没有 Docker）**实测通过**的版本，不是从 README 直接抄的。

---

## 0. 先搞明白：这个项目由几块拼起来

DeerFlow 跑起来需要**三块**（本机学习只需要前两块）：

```
浏览器
  │  http://127.0.0.1:3000
  ▼
┌─────────────────────────────┐
│ 前端 Next.js（frontend/）    │  ← 你看到的网页：登录页、聊天页
└─────────────────────────────┘
  │  /api/... 请求被 rewrite 转发到 ↓
  ▼
┌─────────────────────────────┐
│ 网关 Gateway（FastAPI，8001）│  ← backend/app/gateway
│   ├─ 认证（登录 / Cookie）   │
│   ├─ 会话（thread）与运行(run)
│   └─ 把请求交给 LangGraph 图  │
└─────────────────────────────┘
  │
  ▼
┌─────────────────────────────┐
│ Agent 运行时 harness        │  ← backend/packages/harness/deerflow
│  LangGraph 状态图 + 工具 + 沙箱 + 记忆
└─────────────────────────────┘
  │  HTTPS
  ▼
  大模型 API（本机用的是 DeepSeek）
```

第三块是 `nginx`（生产环境统一入口，端口 2026）。本机学习**不需要它**，因为 Next.js 自带把 `/api/*` 转发到 8001 的能力（见本文第 5 节）。

## 2. 准备两个配置文件（关键，缺一个就启动不了）

### 2.1 `F:\workspace\deer-flow\.env` —— 放大模型的密钥

```
DEEPSEEK_API_KEY=sk-你的key
LANGSMITH_TRACING=false
```

> **知识点**：`.env` 是「环境变量文件」。程序启动时把里面的 `KEY=VALUE` 读进进程环境，
> 代码里用 `$DEEPSEEK_API_KEY`（YAML）或 `os.environ[...]`（Python）读取。
> **好处**：密钥不写进代码，不会被提交到 git。
> `LANGSMITH_TRACING=false` 表示关掉 LangSmith 云端追踪（学习阶段不需要，省流量）。

### 2.2 `F:\workspace\deer-flow\config.yaml` —— 告诉 DeerFlow 用哪个模型、用哪个沙箱

```yaml
# ★ sandbox 是必填项，少了它后端会直接报 ValidationError: sandbox Field required
sandbox:
  use: deerflow.sandbox.local:LocalSandboxProvider   # 在本机执行 Agent 的命令
  allow_host_bash: false                             # 但禁止 Agent 直接跑系统 shell（安全）

models:
  - name: deepseek-v4-pro                 # 内部代号，前端选模型时用这个名字
    display_name: DeepSeek V4 Pro         # 界面上显示的名字
    use: deerflow.models.patched_deepseek:PatchedChatDeepSeek  # 用哪个「模型适配器」
    model: deepseek-v4-pro                # 真正发给 DeepSeek API 的 model 参数
    api_key: $DEEPSEEK_API_KEY            # 从 .env 读取
    timeout: 600.0
    max_retries: 2
    max_tokens: 8192                      # 单次回答最多生成多少 token
    context_window: 131072                # 模型能「记住」多少 token
    supports_thinking: true               # 支持「思考模式」
    supports_vision: false
    when_thinking_enabled:
      extra_body:
        thinking:
          type: enabled
    when_thinking_disabled:
      extra_body:
        thinking:
          type: disabled
```

> **知识点**：
> - `use: deerflow.models.xxx:ClassName` 这种写法是 Python 的「**模块路径:类名**」引用，
>   DeerFlow 用它做**插件式装配**：配置里写字符串，代码里 `importlib` 动态加载。
>   想换模型（OpenAI / 通义 / 本地 vLLM）时，**只改 yaml，不改代码**。
> - `context_window` 和 `max_tokens` 是**上下文窗口**和**最大输出长度**，是 LLM 的两个基础参数（见 `02-知识点总结.md`）。
> - `thinking` 是 DeepSeek 的「思维链」开关：打开后模型会先输出一段推理过程再给答案，更准但更贵。

## 3. 安装依赖（只需做一次）

```powershell
# 后端：Python 依赖，装进 backend/.venv（本机实测约 624MB）
cd F:\workspace\deer-flow\backend
uv sync --locked

# 前端：Node 依赖，装进 frontend/node_modules（本机实测约 1 分半）
cd F:\workspace\deer-flow\frontend
pnpm install
```

> **知识点**：`uv.lock` / `pnpm-lock.yaml` 是**锁文件**，记录每个依赖的精确版本。
> `--locked` 表示「严格按锁文件装，不准自动升级」，保证换台机器装出来一模一样。

**踩坑记录（本机真实遇到）**：
- `uv sync --locked` 从官方 PyPI 下载**很慢**（约 40MB/分钟），这是网络问题，不是卡死，**耐心等**。
- 不要加 `--no-default-groups`，会报 `The lockfile at uv.lock needs to be updated`。
- 清华镜像本机不通（curl 返回 000），所以只能用官方源。

## 4. 启动后端（Gateway，端口 8001）

**开一个 PowerShell 窗口，保持它开着**：

```powershell
cd F:\workspace\deer-flow\backend
uv run --locked uvicorn app.gateway.app:app --host 127.0.0.1 --port 8001
```

看到这两行就成功了：

```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8001 (Press CTRL+C to quit)
```

验证：

```powershell
curl.exe http://127.0.0.1:8001/health
# 期望：{"status":"healthy","service":"deer-flow-gateway"}
```

> **知识点**：
> - `uvicorn app.gateway.app:app` = 「用 uvicorn 这个 ASGI 服务器，跑 `app/gateway/app.py` 里名为 `app` 的对象」。
> - `127.0.0.1` 表示**只允许本机访问**，不对外网开放（学习阶段更安全）。
> - 第一次启动会自动建 SQLite 数据库：`backend/.deer-flow/data/deerflow.db`，并在日志里打印
>   `First boot detected — no admin account exists. Visit /setup`。

## 5. 启动前端（端口 3000）

**再开第二个 PowerShell 窗口**：

```powershell
cd F:\workspace\deer-flow\frontend

$env:DEER_FLOW_INTERNAL_GATEWAY_BASE_URL = "http://127.0.0.1:8001"
$env:DEER_FLOW_TRUSTED_ORIGINS = "http://127.0.0.1:3000,http://localhost:3000"
$env:PORT = "3000"

pnpm dev
```

> ⚠️ **绝对不要设置 `NEXT_PUBLIC_BACKEND_BASE_URL`！**
> 这是本机踩过的最大坑：`frontend/next.config.js` 里有一句判断——
> **只有在这个变量「没有设置」时**，才会注册 `/api/:path*` → `http://127.0.0.1:8001/api/:path*` 的转发规则。
> 一旦设了它，代理规则被关掉，浏览器请求 `/api/v1/auth/setup-status` 直接 **404**，
> 页面就会显示「服务暂时不可用」。**明明后端是好的，却像是后端挂了。**

三个环境变量的含义：

| 变量 | 作用 | 涉及知识 |
|---|---|---|
| `DEER_FLOW_INTERNAL_GATEWAY_BASE_URL` | 服务端（Node 进程）访问后端的地址 | 服务端渲染(SSR)里，请求不是浏览器发的，是 Node 发的 |
| `DEER_FLOW_TRUSTED_ORIGINS` | 允许哪些来源发起跨站请求 | CORS / CSRF 的 Origin 白名单 |
| `PORT` | Next.js 监听端口 | — |

## 6. 创建第一个管理员（只做一次）

打开浏览器 `http://127.0.0.1:3000/setup`，填邮箱和密码，点创建。

**⚠️ 邮箱必须用真实域名，比如 `student@example.com`。**
不要用 `student@local.test` —— `.test` 是**保留域名**，后端用 `email-validator` 校验时会返回：

```
422 value is not a valid email address:
The part after the @-sign is a special-use or reserved name
```

而前端当时**没有把这条错误显示出来**，看起来就像「点了没反应」。这个坑本机踩过一次，记在这里。

密码要求：≥ 8 位，且不能是常见弱密码。本机用的是 `DeerFlow123!`（可用）。

创建成功后会自动登录，跳到 `/workspace`。

## 7. 验证「真的能对话」

在 `/workspace` 的聊天框输入：`请用一句中文介绍你自己`

预期：几秒内出现流式输出，例如「我是 DeerFlow 2.0，一个开源超级智能体……」

如果想用命令行验证（不开浏览器），可以这样：

```powershell
$base="http://127.0.0.1:8001"
$s=New-Object Microsoft.PowerShell.Commands.WebRequestSession

# 1) 登录，拿 Cookie（access_token + csrf_token）
Invoke-RestMethod "$base/api/v1/auth/setup-status" -WebSession $s | Out-Null
Invoke-RestMethod "$base/api/v1/auth/login/local" -Method Post `
  -Body @{username="student@example.com";password="DeerFlow123!";remember_me="true"} `
  -WebSession $s | Out-Null

# 2) POST 请求要带 CSRF 头（防跨站伪造）
$csrf = $s.Cookies.GetCookies($base)["csrf_token"].Value
$h = @{ "X-CSRF-Token" = $csrf }

# 3) 新建会话（注意是 /api/threads，不是 /api/v1/threads）
$t = Invoke-RestMethod "$base/api/threads" -Method Post -Body '{"metadata":{}}' `
  -ContentType "application/json" -Headers $h -WebSession $s

# 4) 发起一次「运行」并等结果
$obj = @{
  assistant_id = "lead_agent"
  input        = @{ messages = @(@{ role="user"; content="用一句话介绍你自己" }) }
  context      = @{ model_name = "deepseek-v4-pro" }
}
$json  = $obj | ConvertTo-Json -Depth 6 -Compress
$bytes = [System.Text.Encoding]::UTF8.GetBytes($json)   # ★ 中文必须转 UTF-8 字节
Invoke-RestMethod "$base/api/threads/$($t.thread_id)/runs/wait" -Method Post -Body $bytes `
  -ContentType "application/json; charset=utf-8" -Headers $h -WebSession $s -TimeoutSec 300
```

返回的 JSON 里 `messages` 最后一个元素就是模型的回答，附带 `response_metadata.token_usage`
（`prompt_tokens` / `completion_tokens` / `total_tokens`）——这就是「**token 计费**」的原始数据。

> **知识点**：这条命令其实把「一次 Agent 运行」拆开看了：
> `创建 thread`（会话，= 一条聊天记录容器）→ `创建 run`（一次执行）→ `wait`（同步等结果）。
> 网页上点「发送」，前端做的正是这两步，只是用 SSE 流式接收，而不是等最后一次性返回。

## 9. 常见错误对照表（都是本机真实遇到的）

| 现象 | 真实原因 | 解决办法 |
|---|---|---|
| 后端启动报 `ValidationError: sandbox Field required` | `config.yaml` 少了 `sandbox:` 段 | 按第 2.2 节补上 |
| 网页显示「服务暂时不可用 / Service temporarily unavailable」 | 曾设置过 `NEXT_PUBLIC_BACKEND_BASE_URL`，导致 `/api` 转发规则失效，请求 404 | 去掉该变量，重启前端 |
| `/setup` 点创建没反应、也没错误提示 | 邮箱用了保留域名（`.test` / `.local` / `.invalid`）→ 后端 422 | 换 `@example.com` 这类真实域名 |
| 登录点了没反应 | 同上：账号根本没建成功 | 先回 `/setup` 用合法邮箱建号 |
| `make` 报错 `不是内部或外部命令` | Windows 没有 make | 按本文直接手敲等价命令 |
| `scripts/check.py` 报 nginx not found / 无 Docker | 本机没装 | 学习阶段忽略，用本文的「3000 直连 8001」方案 |
| `uv sync` 卡在某个包不动 | 官方 PyPI 慢 | 等待；或换网络（镜像本机不通） |
| 命令行发中文，回答却是乱码/一串问号 | PowerShell 5.1 默认用 ANSI 编码发 body | 用 `[System.Text.Encoding]::UTF8.GetBytes($json)` 转字节再发 |

1. 本文档 —— 先把它跑起来，建立「能动手」的信心。
2. `01-架构与文件地图.md` —— 知道每个目录/文件是干嘛的，不要一上来就通读 31 万行。

   → `frontend/src/components/workspace/chats/chat-box.tsx`，这三处是「骨架」。
