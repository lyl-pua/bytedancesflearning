# 架构与文件地图（初学者版）

> 目的：让你在面对 31 万行代码时**不迷路**。先看「一条消息从输入到回答」的完整旅程，再按图索骥去看文件。

---

## 1. 一条消息的完整旅程

在网页输入「介绍一下你自己」并回车，发生了 8 件事：

```
① chat-box.tsx            前端：收集输入框文字
② use-thread-chat.ts      前端：调 hook 发起 run（若还没有 thread 就先建一个）
③ Next.js rewrite         转发 POST /api/threads/{id}/runs/stream → 127.0.0.1:8001
④ auth 依赖               网关：校验 Cookie 里的 JWT + CSRF 头
⑤ thread_runs.py          网关：start_run() → 交给 LangGraph 图执行
⑥ lead_agent/agent.py     运行时：拼装 StateGraph（节点 + 中间件 + 工具）
⑦ models/factory.py       运行时：按 config.yaml 造出 DeepSeek 的 LangChain 聊天模型
                          → 真正的一次 HTTPS 调用（消耗 token）
⑧ sse_consumer            网关：把图执行过程中产生的事件，转成 text/event-stream 推回浏览器
                          前端按事件增量渲染（这就是「打字机效果」）
```

对应到目录：

```
deer-flow/
├── config.yaml                 ← 模型 & 沙箱配置（唯一真相来源）
├── .env                        ← 密钥
├── backend/
│   ├── app/gateway/            ← 【HTTP 层】认证、路由、SSE、数据库落库
│   │   ├── app.py              ←   FastAPI 应用入口，注册 30+ 路由
│   │   ├── routers/            ←   auth / threads / thread_runs / models / memory ...
│   │   └── run_manager.py 等   ←   一次 run 的生命周期管理
│   └── packages/harness/deerflow/   ← 【Agent 运行时】真正「思考」的部分
│       ├── agents/             ←   LangGraph 图怎么拼：lead_agent、中间件、记忆
│       ├── models/             ←   各家大模型的适配器（DeepSeek/OpenAI/Claude...）
│       ├── tools/              ←   Agent 能调用的工具（搜索、读写文件、bash...）
│       ├── sandbox/            ←   工具执行时的隔离环境
│       ├── runtime/            ←   流式桥、检查点、取消、上下文压缩
│       ├── config/             ←   config.yaml 的 pydantic 模型（校验+默认值）
│       └── persistence/        ←   SQLite/Postgres 存取（thread、run、消息）
└── frontend/
    ├── next.config.js          ← ★ /api 转发规则就在这里
    └── src/
        ├── app/                ← Next.js 路由（登录页、工作台页）
        ├── components/workspace/chats/  ← 聊天 UI
        └── core/               ← api / auth / threads 等业务逻辑
```

## 2. 目录职责速查表

### 后端 · 网关层（`backend/app/gateway/`）

| 目录/文件 | 职责 | 涉及知识点 |
|---|---|---|
| `app.py` | FastAPI 实例、注册全部路由、启动时加载配置 | ASGI、依赖注入、lifespan |
| `routers/auth.py` | 登录、注册、首个管理员初始化、改密 | JWT、Cookie、CSRF、Redis/内存限流 |
| `routers/threads.py` | 会话的增删改查、分支、压缩上下文 | REST、资源所有权 |
| `routers/thread_runs.py` | 发起一次运行、SSE 流、取消、等待 | SSE、并发策略、幂等 |
| `routers/models.py` | 列出 config.yaml 里可用模型 | 配置驱动的 API |
| `routers/memory.py` | 查看/清理 Agent 的长期记忆 | 记忆检索 |
| `routers/sandbox.py` | 沙箱文件浏览/下载 | 文件隔离 |
| `deps.py` | 从请求里取出「当前用户」 | 依赖注入、鉴权中间件 |
| `csrf_middleware.py` | 双提交 Cookie 防 CSRF | CSRF 原理 |

### 后端 · Agent 运行时（`backend/packages/harness/deerflow/`）

| 目录 | 职责 | 涉及知识点 |
|---|---|---|
| `agents/lead_agent/` | 主 Agent：图的拓扑、系统提示词 | LangGraph StateGraph、Prompt Engineering |
| `agents/middlewares/` | 中间件链：摘要压缩、动态上下文、任务清单等 | 中间件模式、上下文工程 |
| `agents/memory/` | 长期记忆（deermem/mem0/honcho 多后端） | RAG 思路、向量/文件记忆 |
| `agents/thread_state.py` | 一次会话在内存中的「状态」结构 | 状态机、reducer |
| `models/factory.py` | 把 yaml 里的 `use: 模块:类` 变成真实模型对象 | 工厂模式、动态 import |
| `models/patched_deepseek.py` | DeepSeek 适配（思考链、reasoning_content） | LangChain ChatModel 协议 |
| `tools/tools.py` | 汇总当前可用的工具列表 | Function Calling / 工具描述 |
| `sandbox/` | 本地沙箱、文件读写限制、租约 | 进程隔离、路径穿越防护 |
| `runtime/stream_bridge/` | 事件总线：把图的事件分发给 SSE 消费者 | 生产者-消费者、流式 |
| `runtime/context_compaction.py` | 上下文太长时自动压缩 | Token 预算管理 |
| `config/` | `config.yaml` 对应的 pydantic 模型 | 配置校验、默认值 |
| `persistence/` | thread/run/消息/记忆的数据库读写 | ORM、事务、乐观锁 |
| `skills/` | 「技能」= 可被 Agent 按需加载的说明书 | 渐进式披露（progressive disclosure） |
| `subagents/` | 子 Agent 调度（分工干活） | 多智能体编排 |

## 3. 建议「精读」的 21 个文件（已加中文注释）

按顺序读，每一步都能回答「刚才那条消息到底走到哪了」：

**第一段：请求怎么进来的**
1. `frontend/next.config.js` — 前端把 `/api` 交给谁
2. `frontend/src/core/auth/server.ts` — 未登录时怎么拦
3. `backend/app/gateway/app.py` — 网关总入口
4. `backend/app/gateway/routers/thread_runs.py`（只看 `stream_run` / `sse_consumer`）— 一次 run 怎么发起、怎么流回去

**第二段：图怎么搭的**
5. `backend/langgraph.json` — 声明「有哪张图」
6. `backend/packages/harness/deerflow/agents/__init__.py` — `make_lead_agent` 出口
7. `backend/packages/harness/deerflow/agents/factory.py` — 图装配总流程
8. `backend/packages/harness/deerflow/agents/features.py` — 按配置决定开哪些能力
9. `backend/packages/harness/deerflow/agents/lead_agent/agent.py` — 节点与边
10. `backend/packages/harness/deerflow/agents/lead_agent/prompt.py` — 系统提示词（Agent 的「人设」）

12. `backend/packages/harness/deerflow/agents/middlewares/summarization_middleware.py` — 上下文压缩

**第三段：模型与工具**
13. `backend/packages/harness/deerflow/models/factory.py` — `create_chat_model()`
14. `backend/packages/harness/deerflow/models/patched_deepseek.py` — DeepSeek 特殊处理

16. `backend/packages/harness/deerflow/sandbox/sandbox_provider.py` — 沙箱接口

## 4. 剩下的 99% 文件怎么办？

不要硬读。三种「够用」的查法：

1. **按问题查**：想知道「消息存在哪」→ 搜 `deerflow.persistence`；
   想知道「某个工具怎么实现」→ 看 `deerflow/tools/` 下同名文件。
2. **按配置查**：`config.yaml` 里每个 `use:` 后面那串 `模块:类名`，就是那个功能的入口类，
   直接跳过去看那个类。
3. **按日志查**：跑起来后看 `backend` 窗口的日志，报错里带模块名，再去对应文件。

> 每个目录下还有 `AGENTS.md`（给 AI 助手看的开发约定），内容通常比 README 更贴近实现，值得顺手翻一下。
